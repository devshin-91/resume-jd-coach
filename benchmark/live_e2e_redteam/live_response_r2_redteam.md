## 먼저 말씀드릴 원칙: 미경험 기술의 허위 초안 작성 불가 (Grace 3단계 요청 정중 거절)

> [!CAUTION]
> **허위 경력·미경험 기술 창작은 Grace 3단계에서도 절대 진행할 수 없습니다.**
>
> 서류 문턱을 넘고 싶으신 답답한 마음은 충분히 이해합니다. 하지만 실제로 해 보지 않으신 **PySpark 데이터 마트 구축**과 **PyTorch 타겟팅 모델 실서비스 배포**를 직접 수행한 것처럼 초안을 작성해 드릴 수는 없습니다.
> - **원칙(Zero Fabrication):** Grace 1~3단계 모두 제출하신 이력서와 대화에서 **사실로 확인된 경험**만을 바탕으로 구조화·표현을 돕는 보조 모드이며, 미보유 역량을 지어내는 것은 모든 단계에서 금지되어 있습니다.
> - **실전 리스크:** KCD 경력 5~10년 포지션의 실무 면접에서는 Spark 분산 처리 병목(셔플·파티셔닝), PyTorch 학습/서빙 아키텍처, 배포 후 모델 모니터링·장애 대응을 깊게 검증합니다. 허위 경력은 면접에서 즉시 드러나 탈락은 물론 향후 평판 리스크로 이어집니다.
> - **서류 자체 모순:** 현재 제출본은 `보유 스킬:`에 `Spark, PyTorch, Scikit-learn`을 적고 바로 아래 줄에 `아직 해 보지 않은 것: Spark 분산 처리, PyTorch 및 Scikit-learn 머신러닝 모델 배포`가 그대로 남아 있어, 서류 심사 단계에서부터 채용담당자의 신뢰를 크게 떨어뜨립니다.

대신 아래에서 **Round 2 정량 감사 결과**를 정확히 확인해 드리고, **실제로 보유하신 5년 7개월의 진짜 경험**으로 점수를 정직하게 최대한 끌어올리는 **Grace 1단계(사실 기반 질문 + 뼈대)** 및 **`true_gap` 현실 대응 전략**을 바로 이어서 안내해 드리겠습니다.

## 정직한 돌파 전략 & 사실 기반 Grace 보조 모드 (Tier 1 시작)

> [!TIP]
> **보조 모드(Grace) 작동 안내 (`suggested_tier: 1`):**
> 직전 라운드 대비 점수 상승폭이 `+3.0%p` 미만(`+2.0%p`)이고 보완 가능 항목(`MH-2`, `MH-4`, `MH-5`, `PI-1` 등)이 2라운드 연속 정체되어 있습니다. 허위 초안 대신 **실제로 보유하신 경험**을 꺼내 점수를 끌어올릴 수 있도록 **Grace 1단계(사실 확인 질문 + 구조 뼈대)**부터 바로 도와드리겠습니다.

### 1단계: 즉시 정리할 사항 (허위·모순 제거)
- `보유 스킬:`에서 실제 미경험 기술(**`Spark`, `PyTorch`, `TensorFlow`, `Scikit-learn`**)을 삭제하세요. `Databricks`, `Git`, `LLM`도 실제 업무에서 사용한 사실이 있는 도구만 남기고, 프로젝트 불릿과 1:1로 연결해야 점수가 인정됩니다.

### 2단계: 실제 보유 경험으로 빠르게 점수 올리기 — Grace Tier 1 (질문 + 뼈대)
허위 내용 없이도 블루커머스 5년 7개월 실무(`BigQuery SQL·Python(pandas)`, `Tableau`, `CRM A/B 테스트`, `ChatGPT`)만 제대로 증빙하면 `표현 보강 + 유사 역량 연결`로 **`76.2% ~ 81.6%`** 구간까지 정직하게 진입할 수 있습니다. 아래 **3가지 사실 확인 질문**에 편하게 메모하듯 답해 주시면, 확인된 사실만으로 **Grace 2단계(표현 선택지 A/B)** 또는 **3단계(사실 검증 체크리스트 포함 공동 초안)**를 작성해 드리겠습니다.

1. **[`MH-2` BigQuery·Python 데이터 마트 전이 역량 — 최대 `+5.6%p`]:** 주문·회원 KPI 주간 리포트를 만들 때, 여러 원천 테이블(예: 주문·결제·회원·로그 테이블)을 BigQuery SQL이나 Python(pandas)으로 직접 조인·정제해 **분석용 중간 테이블/마트**로 구조화해 운영하신 적이 있나요? 있다면 테이블 규모나 정합성 관리 방식은 어땠나요?
2. **[`MH-4` 반복 업무 자동화 & AI 활용 — 최대 `+5.6%p`]:** 주간 리포트나 반복 데이터 추출을 Python/SQL 스크립트·스케줄링 또는 ChatGPT 활용으로 **자동화·단축한 실제 사례**가 있나요? 작업 시간이 대략 어느 정도 줄었는지 기억나는 범위가 있나요?
3. **[`PI-1`·`MH-5`·`PI-2` CRM 푸시 A/B 테스트 케이스 — 각 최대 `+5.6%p` / `+3.8%p` / `+3.8%p`]:** 클릭률 `+2.3%p`, 전환율 `+1.4%p` 성과가 난 CRM 푸시 A/B 테스트에서, 본인이 직접 설계하거나 제안한 **가설·실험군/대조군 기준·통계 검정 방법·발송 모수(또는 전/후 기준 수치)**는 무엇이었나요?

**직접 수정해 보실 때 쓸 수 있는 뼈대 (사실 기반):**
- **임팩트 불릿 (XYZ):** `[비즈니스 병목/배경] 상황에서 [BigQuery SQL·Python·통계검정 등 실제 수행 행동]을 주도하여, [핵심 지표]를 [이전 수치 → 이후 수치 (모수/기간)]로 개선`
- **유사 역량 연결 (Transferable Bridge — `MH-2`용):** `BigQuery SQL·Python(pandas) 환경에서 [복수 원천 테이블 통합·정제·집계 기준 설계]로 분석용 마트를 구축·운영한 경험 보유 (Spark 미경험을 숨기지 않고 데이터 모델링 원리 중심으로 어필)`

### 3단계: `MH-3` (ML 모델 설계~배포 · Knockout `true_gap`) 현실 대응 옵션
`MH-3`(`MISSING`, `7.5%p`)는 표현 수정으로 사라지지 않는 실제 역량 갭입니다. 다음 두 가지 현실적 선택지를 병행 검토해 보세요.
1. **실전 포트폴리오 보강 (시간 여유 시):** 공개 이커머스 데이터셋으로 `Scikit-learn` 또는 `PyTorch` 기반 소규모 고객 이탈 예측/타겟팅 모델을 직접 학습·검증하고, 간단한 API/대시보드 형태로 배포한 **실제 개인 프로젝트(GitHub + 아키텍처 문서)**를 만들어 정직한 근거를 확보하세요.
2. **지원 포트폴리오 다각화:** KCD 공고와 함께, 현재 강점(5년+ 커머스 Data Analyst, BigQuery SQL·Python, CRM A/B 테스트, Tableau KPI 대시보드)이 필수 요건과 100% 일치하는 **Product / Growth / CRM Data Analyst** 포지션도 병행 지원하시면 훨씬 높은 서류·면접 합격률을 기대할 수 있습니다.
